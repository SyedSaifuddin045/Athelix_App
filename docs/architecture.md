## Layer Details

### Layer 1: Generated Endpoints (`src/api/endpoints/`)
- Auto-generated by Orval from `http://localhost:8000/openapi.json`
- One file per OpenAPI tag (auth, users, exercises, etc.)
- Raw async functions returning `{ data, status, headers }`
- Read-only — never edit manually

### Layer 2: Fetch Client (`src/api/client.ts`)
- `apiFetch()`: Custom fetch wrapper with:
  - Automatic `Authorization: Bearer <token>` header
  - 401 retry with Clerk token refresh
  - FastAPI error normalization → `ApiError` class
  - Field-level error extraction for forms
- `apiMutator()`: Wraps `apiFetch` for Orval's mutator interface
- `installApiFetchInterceptor()`: Replaces `globalThis.fetch`

### Layer 3: React Query Hooks (`src/api/queries.ts`)
- 18 query hooks wrapping generated endpoints
- Consistent pattern: `useXQuery(enabled)` or `useXQuery(params, enabled)`
- `enabled` flag gates queries behind auth state
- `SuccessData<T>` utility extracts data from `{ data, status, headers }` union

### Layer 4: Screens (`src/screens/`)
- Consume React Query hooks
- Render UI primitives from `src/components/ui/`
- Handle loading/error/empty states via `Card` variants
- Mutations via inline `useMutation` (to be centralized)

## Auth Architecture

```
ClerkProvider
  └── AuthGate (in AppNavigator.tsx)
       ├── Loads Clerk session
       ├── Extracts JWT via getToken()
       ├── Updates apiFetch token via updateClerkToken()
       └── Sets 10-min token refresh interval

apiFetch (client.ts)
  ├── isPublicPath() → skip auth for /meta, /health, /
  ├── Attaches Authorization header
  ├── On 401: calls refreshTokenHandler (Clerk.getToken)
  ├── Retries once with new token
  └── Falls back to ApiError("Session expired")
```

## Data Mapping Architecture

```
API Response (snake_case)  →  local types (camelCase via mapping.ts)
ExerciseResponse           →  ExerciseItem (via mapExerciseItem)
ExerciseDetailResponse     →  ExerciseDetail (via mapExerciseDetail)
WorkoutTemplateDetail      →  TemplateDraftExercise (via templateDraftFromDetail)
WorkoutTemplateDetail      →  WorkoutDraftExercise (via workoutDraftFromTemplate)
ExerciseSetResponse[]      →  grouped by exercise (via groupSetsByExercise)
```

## Query Key Structure

Centralized in `src/api/queryKeys.ts` using `as const` tuples:
```
["resource", "subresource", id?, params?]
```

Examples:
- `["users", "me", "overview"]` — user overview
- `["workout-templates", 42]` — specific template
- `["exercises", { target: "Chest" }]` — exercise list with filters
