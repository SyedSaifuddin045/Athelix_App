Muscle Balance Screen — SVG Integration

Design options for embedding the full-body SVG into the existing MuscleBalanceScreen

Current State

The MuscleBalanceScreen shows a flat list of muscle group cards. Each card has a score %, status tag (Strong/Balanced/Needs Attention), a volume bar, and expandable exercise rows.

Layout
  • • Period selector (1W/2W/4W/8W)
  • • Scrollable list of muscle group cards
  • • Each card = score + status + volume bar
  • • Expandable exercise detail rows
Data
  • • 10 muscle groups from API
  • • Score 0-100, status, weekly sets
  • • Exercises with completed_sets
  • • Uses muscleAccentColor mapping

Full_Body.svg — Structure

The SVG is a 1280 × 832 single-layer illustration with 112 path elements. Muscle regions are drawn in #E8E8E8 (light outline), with #0F0E0F separator lines and #3A3A3A background. There are no semantic IDs on individual muscle paths.

Background / outline (4 paths)
Detail highlights (2 paths)
Accessory details (4 paths)
Gradient fills (2 paths)

Integration requires assigning muscle group IDs to relevant paths so React Native can apply per-group fill colors and touch handling.

Three Approaches

A — SVG as Visual Header

MINIMAL

Place the SVG at the top of the scrollable area as a static visual reference. The existing card list below remains unchanged. The SVG shows a color-coded heatmap of all muscle groups based on their scores.

Screen Layout
SVG Heatmap color-coded by score
  • Quick to implement
  • No path-ID mapping needed
  • Doesn't change existing UX
  • No interactivity
  • SVG is purely ornamental
  • User can't tap to filter

B — Interactive SVG + Condensed List RECOMMENDED

BALANCED

SVG body becomes interactive: each muscle region responds to taps. Tapping a region highlights it and scrolls or filters the list to that group. A compact representation of the current card list sits below, with expandable exercise rows. The SVG uses react-native-svg with Pressable wrappers on each path group.

Idle State
muscle groups colored by score
After Tapping "Chest"
✦ Chest selected
  • Direct visual-to-data connection
  • Fast muscle group navigation
  • Maintains existing card detail
  • Feels polished and premium
  • Requires path ID mapping (1-2h)
  • Complex component structure
  • SVG touch areas need native coords

C — Full SVG Heatmap, No List

BOLD

Replace the entire card list with a large, fully interactive SVG. Each muscle region is tappable and shows a floating tooltip/popover with score + sets. The list is removed — all navigation is visual. Detailed exercise data shown in a bottom sheet on tap.

Full-Screen SVG
Large interactive SVG tap any muscle → score tooltip tap again → bottom sheet with exercises
  • Most visually impressive
  • Good for smaller screens
  • Unique UX differentiator
  • Loses quick-scan list view
  • Harder to compare groups side-by-side
  • More development time
  • Exercise detail hidden behind tap

Implementation Sequence (Recommended Approach B)

1. Annotate SVG paths

Add id and data-muscle attributes to each relevant path group in the SVG. Group related paths (e.g., left/right pecs → "Chest"). ~1-2h manual work.

2. Create MuscleSVG component

React Native wrapper using react-native-svg. Import SVG as component, add fill overrides per muscle ID based on score/color data.

3. Add touch handlers

Wrap each muscle path group in Pressable. On tap: update selected state, trigger list scroll via ref.scrollToItem or Animated scroll.

4. Integrate into MuscleBalanceScreen

Replace current card-list-only layout with SVG header + condensed list. Wire up state: selected muscle ↔ SVG highlight ↔ list scroll.

5. Polish animations

Animated transitions for SVG fill changes, list scroll, selected state. Use Reanimated for smooth 60fps.

Open Questions

  • Q Should scroll-to-muscle use SectionList.scrollToLocation or Animated.ScrollView.scrollTo? (SectionList better for performance, ScrollView simpler for dynamic heights).
