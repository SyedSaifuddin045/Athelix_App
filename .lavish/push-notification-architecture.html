How It Works — Step by Step

1

Device Registration

When a user opens the app, it requests OS notification permission, then calls getDevicePushTokenAsync() to obtain the raw FCM token from Google Play Services. This token is registered with the backend via POST /devices/register along with platform, device name, and app version.

2

Token Persistence

The backend NotificationRepository upserts device records by (user_id, push_token). Same user + same token updates last_seen. Same user + new token creates a fresh record. One user can own many devices — tokens are not stored on the User table.

3

Token Refresh Handling

FCM tokens can change (app update, device restore). The app listens for PushTokenListener events. When a token changes, the old token is unregistered (POST /devices/unregister) and the new one is registered — preventing stale token accumulation.

4

Sending Notifications

Business logic calls a single method: NotificationService.send_to_user(user_id, title, body, data). The service:

  • Queries all active device tokens for the user
  • Routes to the correct provider by platform (android → FCM, ios → APNs)
  • Logs every send attempt to notification_history with status and errors
  • Auto-deletes tokens that FCM reports as unregistered or invalid
5

FCM Delivery

The FCMProvider constructs a Firebase messaging.Message with title, body, and data payload, then calls messaging.send(). The HTTP v1 API delivers the notification to the Android device via Google Play Services.

6

Deep Link Navigation

When a user taps a notification, the useNotificationTapHandler hook reads the data payload from the notification. The screen field determines which screen to navigate to, with params like sessionId, templateId, etc. This works from foreground, background, and killed states.

The Provider Pattern

A

Abstract Provider

class NotificationProvider(ABC):
    @abstractmethod
    async def send(
        token, title, body, data
    ) -> ProviderResult:
        ...

Single interface. Any provider — FCM, APNs, or future — implements this one method.

B

FCM Provider Live

class FCMProvider:
    async def send(...):
        message = Message(
            notification=Notification(title, body),
            data=payload,
            token=token,
        )
        response = messaging.send(message)

Uses Firebase Admin SDK. Handles UnregisteredError, InvalidArgumentError automatically.

C

APNs Provider Stub

class APNsProvider:
    async def send(...):
        raise NotImplementedError(
            "APNs not yet implemented"
        )

Placeholder for iOS. Implement send() using Apple's HTTP/2 API — no business logic changes needed.

Design Principles

🔌 Provider Agnostic

Business logic never calls Firebase directly. The abstract NotificationProvider interface means you can swap FCM for any future provider by implementing one method.

📋 Full Audit Trail

Every notification send is logged to notification_history with status, provider response, and error details — enabling debugging, analytics, and delivery tracking.

🧹 Self-Cleaning

Invalid and unregistered tokens are automatically deleted from the database when FCM rejects them. No manual cleanup or cron jobs needed.

⚡ Async Ready

All method signatures are async from day one. Trivially dispatchable to background workers (Celery, Arq, Dramatiq) without refactoring.

📱 Multi-Device

One user can own many devices. Tokens are stored separately from the User table with proper foreign key constraints and cascade delete.

🔐 Zero Vendor Lock-In

Uses raw FCM tokens via getDevicePushTokenAsync() instead of Expo push tokens. You own your token infrastructure.
