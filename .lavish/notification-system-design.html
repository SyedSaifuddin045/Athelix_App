🔑 Key Design Decision

Business logic never touches Firebase. It calls notification_service.send(user_id, title, body, data) — provider selection, token lookup, and error handling happen inside the notification module.

app/notifications/providers/fcm.py Implementation 
import logging
from firebase_admin import credentials, initialize_app, messaging
from .base import NotificationProvider, ProviderResult

logger = logging.getLogger(__name__)


class FCMProvider(NotificationProvider):
    """Send push notifications via Firebase Cloud Messaging."""

    def __init__(self, service_account_json: dict):
        cred = credentials.Certificate(service_account_json)
        self.app = initialize_app(credential=cred)

    async def send(
        self,
        token: str,
        title: str,
        body: str,
        data: dict | None = None,
    ) -> ProviderResult:
        try:
            msg = messaging.Message(
                notification=messaging.Notification(
                    title=title, body=body
                ),
                data=data,
                token=token,
            )
            response = messaging.send(msg)
            return ProviderResult(
                success=True,
                provider_response=response,
            )
        except messaging.UnregisteredError as exc:
            logger.warning("Token unregistered: %s", exc)
            return ProviderResult(
                success=False,
                error="NotRegistered",
            )
        except Exception as exc:
            logger.error("FCM send failed: %s", exc)
            return ProviderResult(
                success=False,
                error=str(exc),
            )

app/notifications/service.py Core 
class NotificationService:
    """Orchestrates push notification delivery across providers."""

    def __init__(
        self,
        repository: NotificationRepository,
        providers: dict[str, NotificationProvider],
    ):
        self._repository = repository
        self._providers = providers

    async def send_to_user(
        self,
        user_id: int,
        title: str,
        body: str,
        data: dict | None = None,
    ) -> SendResult:
        devices = self._repository.get_active_devices(user_id)
        results = []

        for device in devices:
            provider = self._providers.get(device.platform)
            if not provider:
                continue

            result = await provider.send(
                token=device.push_token,
                title=title,
                body=body,
                data=data,
            )

            # Log to history
            self._repository.save_history(
                user_id=user_id,
                title=title,
                body=body,
                data=data,
                provider=device.platform,
                status="sent" if result.success else "failed",
                provider_response=result.provider_response,
                error=result.error,
            )

            # Delete invalid tokens
            if not result.success and result.error in {
                "NotRegistered", "InvalidToken"
            }:
                self._repository.delete_device(device.id)

            results.append(result)

        return SendResult(
            total=len(devices),
            sent=sum(1 for r in results if r.success),
            failed=sum(1 for r in results if not r.success),
        )

🎯 Retry Strategy — Ready for Background Workers

The send_to_user method is a single async function — trivially dispatchable to Celery, Arq, Dramatiq, or any task queue later. No HTTP request will block while sending. The method signature stays the same; only the caller changes from await service.send_to_user(...) to queue.enqueue(service.send_to_user, ...).

Error Handling & Edge Cases
Production reliability patterns

🔥 Invalid Tokens

FCM returns UnregisteredError when token is stale. Provider returns "NotRegistered" error → NotificationService deletes device from DB automatically.

⏱️ Rate Limiting

SlowAPI middleware already configured (120 req/min). FCM has its own rate limits (600 msg/s per project). NotificationService is designed for queued dispatch when volume grows.

📵 No Devices

If user has no registered devices, send_to_user returns SendResult(total=0, sent=0, failed=0) — no error thrown. Silent no-op.

🔐 Missing Provider

If FCMProvider fails to initialize (bad credentials), send_to_user skips that platform. Logged and captured by Sentry.
